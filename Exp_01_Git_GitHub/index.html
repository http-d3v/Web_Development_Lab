Step-by-Step Practical Implementation

STEP 1 Initializing Local Repository and Configuring Remotes

Create the project folder, initialize a fresh Git repository, verify `.gitignore`, and link the local directory to the remote repository on GitHub. 

# Initialize local repository and set default branch to main
git init -b main

# Add all files to the staging area (index)
git add .

# Create the first root commit
git commit -m "feat: initial commit with project structure and static site files"

# Connect the remote GitHub repository
git remote add origin https://github.com/http-d3v/Web_Development_Lab.git

# Verify configured remote URLs
git remote -v
Tip: Always create a clean .gitignore before staging files to avoid pushing node_modules/, logs, or system cache files like .DS_Store.

STEP 2 Feature Branching and Isolated Development

Never develop experimental features directly on the main branch. Creating a dedicated feature branch isolates your code so broken experiments do not disrupt the production deployment. 

# Create and switch to a new feature branch
git checkout -b feature/portfolio-cards

# Check which branch is active (indicated by asterisk *)
git branch

# Make changes to HTML/CSS files, then stage and commit
git add index.html style.css
git commit -m "feat(portfolio): add responsive card grid and styling"
Under the Hood: A Git branch is just a 41-byte pointer to a commit hash. Switching branches updates the .git/HEAD file to point to the new ref.

STEP 3 Merging Feature Branch into Main

Once the feature is tested and verified, switch back to main and merge the changes. If no divergent commits exist on main, Git performs a clean fast-forward merge. 

# Switch back to the production branch
git checkout main

# Merge the completed feature into main
git merge feature/portfolio-cards

# Push the merged history to GitHub
git push origin main

# Delete the feature branch locally once merged
git branch -d feature/portfolio-cards
Conflict Resolution: If both branches modified the same line, Git pauses the merge. Open the file, resolve conflict markers (<<<<<<<, =======, >>>>>>>), stage with git add, and run git commit.

STEP 4 Configuring GitHub Pages for Static Site Hosting

GitHub Pages provides free static hosting for web applications directly from a branch in your repository. 

1. Navigate to repository on GitHub: github.com/http-d3v/Web_Development_Lab
2. Click on "Settings" tab in the top navigation bar.
3. In the left sidebar, click "Pages" under the "Code and automation" section.
4. Under "Build and deployment" > "Source", select "Deploy from a branch".
5. Set Branch to: "main" and folder to: "/ (root)" (or "/docs" if configured).
6. Click "Save". GitHub Actions will automatically build and deploy.
7. Deployed site URL: https://http-d3v.github.io/Web_Development_Lab/
Enforce HTTPS: Always check the "Enforce HTTPS" checkbox in the GitHub Pages settings to ensure all traffic is encrypted with SSL.

Core Git Command Reference

Command Category Description & Practical Use
git init -b main Setup Initializes a new Git repository with default branch named main.
git clone <url> Setup Clones an existing remote repository onto your local development machine.
git status Inspection Displays modified, untracked, and staged files in the working directory.
git add -A Staging Stages all new, modified, and deleted files ready for commit.
git commit -m "msg" Recording Records a snapshot of the staged changes with a descriptive commit message.
git branch -a Branching Lists all local and remote tracking branches in the repository.
git checkout -b <name> Branching Creates a new branch and immediately checks it out (switches to it).
git merge <branch> Integration Merges the specified branch's commits into the currently checked-out branch.
git log --oneline --graph History Shows a compact visual ASCII tree of the commit history and branch merges.
git push -u origin <branch> Remote Pushes commits to GitHub and sets up upstream tracking for future simple git push.
